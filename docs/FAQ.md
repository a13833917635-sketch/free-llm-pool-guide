# FAQ · 常见坑与答疑

## Q1：为什么请求一直报 401 / 鉴权失败？
**A**：九成是密钥没填对。逐个查：
- 客户端填的 Key 是不是你配置里 `master_key` 那个？
- 上游渠道的 Key 是不是过期了、或复制时带了空格？
- 配置文件里的 `YOUR_XXX_HERE` 是不是忘了替换？

## Q2：为什么用一会儿就被上游封 / 报 429？
**A**：撞到平台的**频率限制（RPM）**了。把限流代理里对应模型的 `rpm` 调低，
让请求慢下来。**贪快是白嫖被封的头号原因。**

## Q3：为什么有的模型能用有的不能用？
**A**：
- 检查聚合网关里那个渠道是不是「已启用」且测试通过；
- 检查限流代理配置里 `model_name` 拼写和客户端填的是否一致；
- 那个免费源本身可能临时挂了或额度用完了。

## Q4：能把限流代理暴露到公网给朋友一起用吗？
**A**：**不建议直接裸奔**。公网暴露等于把你的池子敞开，任何人拿到地址就能薅你的额度。
真要共享，请在前面加一层鉴权 / 反向代理，并务必用强 `master_key`。

## Q5：配置文件里的真实密钥会不小心传到网上吗？
**A**：只要你：
- 用的是 `.example.yaml` 模板（全占位符）；
- 真实配置文件已被 `.gitignore` 忽略；
- 推送前 `git status` 检查没把真实配置加进去；
就不会。**万一误提交，立刻去平台吊销换新 Key。**

## Q6：为什么叠两层（聚合 + 限流），一层不行吗？
**A**：聚合层管「多源合并」，限流层管「频率精控 + 统一观测」。
分开后你能精确到「每个上游每分钟几次」，单纯聚合面板做不到这么细。

## Q7：这些免费额度会不会哪天全没了？
**A**：会的，免费额度随时可能变动或取消。所以这套架构的价值在于**可替换**——
某个源没了，就在聚合网关里换一个新的，客户端地址不用动。
